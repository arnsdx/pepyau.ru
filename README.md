# Случайная картинка

Каждый запрос к `/` выбирает случайную запись в SQLite и возвращает страницу с одним изображением. Размеры подгоняет короткий скрипт, центрирование задают HTML-атрибуты. CSS в проекте отсутствует.

## Запуск через Docker Compose

Запустите Docker Compose из корня проекта.

~~~sh
docker compose up -d --build
~~~

Откройте [http://127.0.0.1:8080/](http://127.0.0.1:8080/). nginx принимает запросы, Waitress запускает приложение Python 3.12. По умолчанию подключается соседняя папка `../Pinterest_large`. Файлы изображений остаются на диске хоста, а приложение видит каталог через монтирование только для чтения. В Linux для этого подходит локальная файловая система, например ext4.

Чтобы изменить настройки, скопируйте `.env.example` в `.env` рядом с `compose.yaml`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `IMAGES_DIR` | `../Pinterest_large` | Существующий каталог изображений на хосте. |
| `INDEX_INTERVAL_SECONDS` | `300` | Пауза между завершением одного обхода и началом следующего. `0` отключает таймер. |
| `HTTP_BIND` | `127.0.0.1` | Адрес, на котором хост принимает запросы к nginx. |
| `HTTP_PORT` | `8080` | Порт nginx на хосте. |

Для публичного доступа nginx можно подключить к внешнему HTTPS-прокси. SQLite хранится в постоянном локальном томе `catalog`. Остановка и пересоздание контейнеров сохраняют этот том.

## Запуск без Docker

Для локального запуска нужен Python 3.12. Выполните команды из корня проекта.

~~~sh
python -m pip install -r requirements.txt
python app.py serve
~~~

Приложение откроется на том же адресе. При прямом запуске папку изображений и базу можно указать через переменные окружения `IMAGES_DIR` и `DB_PATH`. По умолчанию это `../Pinterest_large` и `data/catalog.sqlite3`. Адрес и порт можно задать параметрами `--host` и `--port`.

## Индексация

Полный обход запускается при старте и затем по таймеру. Администратор может запустить обход вручную.

~~~sh
docker compose exec app python app.py index
~~~

При запуске без Docker используйте `python app.py index` с теми же переменными окружения, что у сервера.

Обход включает подкаталоги и проверяет расширение и сигнатуру JPEG, PNG, GIF и WebP. Символические ссылки и точки соединения каталогов пропускаются. Для обновления изображений записывайте готовый файл во временное имя без индексируемого расширения и затем переименовывайте его в целевое имя. Так сканер и HTTP-запросы увидят готовые файлы.

Запись в SQLite блокируется перед обходом, поэтому ручной запуск и таймер выполняются по очереди. Режим WAL позволяет HTTP-запросам читать предыдущую версию индекса до фиксации транзакции. Ошибка обхода откатывает транзакцию. Успешный обход пустой папки очищает индекс.

Идентификатор картинки вычисляется из относительного пути. Замена содержимого по тому же пути сохраняет URL, а удаление записи при переиндексации делает прежний URL недоступным. Копии одного изображения по разным путям участвуют в выборе отдельно. `ORDER BY RANDOM() LIMIT 1` сканирует весь индекс и может выбрать ту же картинку при обновлении страницы.

## HTTP-маршруты

| Маршрут | Ответ |
| --- | --- |
| `GET /` | Страница с одним изображением. Если в индексе нет записей, HTTP 503. |
| `GET /image/<id>` | Байты выбранного файла. Если запись или файл отсутствуют, HTTP 404. |
| `GET /fit.js` | Скрипт подгонки размера картинки под окно. |
| `/api/v2` | Для любого метода HTTP 401 и JSON `{"code":401,"error":"Unauthorized"}`. HEAD передаёт только заголовки. |

Проверить заглушку можно через curl.

~~~sh
curl -i http://127.0.0.1:8080/api/v2
~~~

sequenceDiagram
    actor Browser as Браузер
    participant Nginx as nginx
    participant App as Python / Waitress
    participant DB as SQLite
    participant Files as Каталог изображений
    Browser->>Nginx: GET /
    Nginx->>App: GET /
    App->>DB: Выбрать случайную запись
    DB-->>App: id изображения
    App-->>Nginx: HTML с /image/id
    Nginx-->>Browser: HTML
    Browser->>Nginx: GET /image/id
    Nginx->>App: GET /image/id
    App->>DB: Найти путь и MIME по id
    DB-->>App: Относительный путь и MIME
    App->>Files: Открыть файл
    Files-->>App: Байты изображения
    App-->>Nginx: Изображение
    Nginx-->>Browser: Изображение
~~~
