# Случайная картинка

Каждый запрос к `/` выбирает случайную запись в SQLite и возвращает страницу с одним изображением. Размеры подгоняет короткий скрипт, центрирование задают HTML-атрибуты. CSS в проекте отсутствует.

## Запуск через Docker Compose

Положите подготовленные к публикации изображения в `./images` или задайте `IMAGES_DIR` с путём к отдельной публичной папке. По умолчанию папка пуста. Сервер отдаёт файлы целиком, поэтому перед добавлением удалите приватные метаданные, если они есть.

Для первого запуска создайте внешний том и импортируйте пару PEM. В примере замените `/absolute/path/to/certs` на абсолютный путь к папке вне репозитория с файлами `fullchain.pem` и `privkey.pem`. Сертификат должен соответствовать имени сайта, а ключ должен быть доступен nginx без ввода пароля. Импорт проверяет пару и создаёт `current.conf` в TLS-томе. Compose запускает nginx после успешной подготовки тома.

~~~sh
docker volume create random-image-tls
docker compose run --rm --no-deps -v "/absolute/path/to/certs:/incoming:ro" tls-import /incoming
docker compose up -d --build
~~~

Последний аргумент `tls-import` задаёт путь внутри контейнера. Путь хоста указывается слева от `:/incoming:ro` и должен существовать на машине, где работает Docker Engine.

Если сертификат выпущен Certbot, подключите весь `/etc/letsencrypt` на время импорта. Так ссылки из `live` смогут указывать на файлы в `archive`. Используйте имя каталога сертификата, которое показывает `certbot certificates`.

~~~sh
docker compose run --rm --no-deps \
  -v /etc/letsencrypt:/etc/letsencrypt:ro \
  tls-import /etc/letsencrypt/live/pepyau.ru
~~~

HTTP доступен только на `http://127.0.0.1:8080/`. HTTPS по умолчанию слушает `127.0.0.1:8443`. Для внешнего доступа задайте `HTTPS_BIND` и обращайтесь по имени из сертификата, например `https://localhost:8443/` при локальной проверке сертификата на `localhost`. Для локальной привязки портов используйте Docker Engine 28.0.0 или новее.

Чтобы изменить настройки, скопируйте `.env.example` в `.env` рядом с `compose.yaml`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `IMAGES_DIR` | `./images` | Существующая папка с публичными файлами. nginx и приложение обслуживают только индексированные изображения. |
| `INDEX_INTERVAL_SECONDS` | `300` | Пауза между завершением одного обхода и началом следующего. `0` отключает таймер. |
| `HTTP_PORT` | `8080` | Локальный порт HTTP на хосте. |
| `HTTPS_BIND` | `127.0.0.1` | Адрес для HTTPS. При отсутствии переменной используется ранее заданный `HTTP_BIND`, если он есть. |
| `HTTPS_PORT` | `8443` | Порт HTTPS на хосте. |
| `TLS_VOLUME_NAME` | `random-image-tls` | Имя внешнего тома с сертификатом и ключом. |

Для другого имени TLS-тома укажите его при создании тома и в `TLS_VOLUME_NAME`. nginx монтирует сертификаты только для чтения. SQLite хранится в постоянном томе `catalog`.

### Обновление и откат TLS

Выполняйте импорт и откат по очереди. Запустите ту же команду `tls-import /incoming` с новыми PEM-файлами. Импорт проверяет пару через `nginx -t` и атомарно меняет файл, указывающий на неё. После успешного импорта перечитайте конфигурацию.

~~~sh
docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload
~~~

Для отката к предыдущей паре выполните `docker compose run --rm --no-deps tls-import --rollback`, затем повторите проверку и reload. Проверяйте сроки действия и соответствие имени отдельно. Сохранённые каталоги старых пар содержат закрытые ключи, поэтому том следует защищать как хранилище ключей.

### Переход с прежней конфигурации

Если `fullchain.pem` и `privkey.pem` уже лежат в корне TLS-тома, `docker compose up -d` импортирует их в версионированную структуру при отсутствии `current.conf`. Для ручного восстановления выполните `docker compose run --rm --no-deps tls-import /etc/nginx/tls`, затем `docker compose up -d nginx`. Если том пуст, возьмите PEM-файлы из источника сертификата и выполните команды первого запуска с тем же `TLS_VOLUME_NAME`.

Остановите прежний бэкенд перед переходом SQLite с WAL на rollback journal. При новом запуске SQLite сменит режим самостоятельно. Выберите папку публичных изображений перед запуском.

### Лимиты

nginx пропускает до 5 запросов в секунду на IP и 50 на сервер с допуском на короткий всплеск. Одновременных запросов может быть до 8 на IP и 64 на сервер. При превышении лимита nginx отвечает `429`. Тело запроса ограничено 16 КиБ и не передаётся приложению. При использовании внешнего прокси лимиты по IP применяются к адресу прокси, пока в nginx явно не настроены доверенные адреса.

## Запуск без Docker

Для локального запуска нужен Python 3.12. Выполните команды из корня проекта.

~~~sh
python -m pip install -r requirements.txt
python app.py serve
~~~

Приложение откроется на том же адресе. При прямом запуске папку изображений и базу можно указать через переменные окружения `IMAGES_DIR` и `DB_PATH`. По умолчанию это `./images` и `data/catalog.sqlite3`. Адрес и порт можно задать параметрами `--host` и `--port`.

## Индексация

Полный обход запускается при старте и затем по таймеру. Администратор может запустить обход вручную.

~~~sh
docker compose exec app python app.py index
~~~

При запуске без Docker используйте `python app.py index` с теми же переменными окружения, что у сервера.

Обход включает подкаталоги и проверяет расширение и сигнатуру JPEG, PNG, GIF и WebP. Файлы тяжелее 10 МиБ, имена с точкой в начале, символические ссылки и точки соединения каталогов пропускаются. Для замены запишите готовый файл во временное имя без индексируемого расширения и затем переименуйте его в целевое имя. В Linux файлы открываются относительно дескриптора корневой папки без перехода по ссылкам. При локальном запуске Windows право записи в папку следует оставить только доверенному оператору.

SQLite резервирует запись перед обходом, поэтому ручной запуск и таймер выполняются по очереди. Во время обхода HTTP-запросы могут читать опубликованный индекс. Фиксация в режиме rollback journal может кратковременно блокировать чтение. Ошибка обхода откатывает транзакцию. Успешный обход пустой папки очищает индекс.

Идентификатор картинки вычисляется из относительного пути. Замена содержимого по тому же пути сохраняет URL, а удаление записи при переиндексации делает прежний URL недоступным. Копии одного изображения по разным путям участвуют в выборе отдельно. Индексатор выдаёт записям смежные `rowid`, поэтому сервер выбирает случайную запись по ключу без полного сканирования. При обновлении страницы та же картинка может выпасть снова.

## HTTP-маршруты

| Маршрут | Ответ |
| --- | --- |
| `GET /` | Страница с одним изображением. Если в индексе нет записей, HTTP 503. |
| `GET /image/<id>` | Байты выбранного файла. Если запись или файл отсутствуют, HTTP 404. |
| `GET /fit.js` | Скрипт подгонки размера картинки под окно. |
| `/api/v2` | В пределах лимитов nginx для любого метода HTTP 401 и JSON `{"code":401,"error":"Unauthorized"}`. HEAD передаёт только заголовки. |

Проверить заглушку можно через curl.

~~~sh
curl -i http://127.0.0.1:8080/api/v2
~~~

## Проверка

Выполните регрессионные тесты из корня проекта.

~~~sh
python -B -m unittest discover -s tests -v
~~~

Тест открытия файла относительно дескриптора каталога требует Linux. Для сопровождения обновляйте зафиксированные версии образов в `compose.yaml` и `Dockerfile` по мере выхода исправлений безопасности. Проверяйте версию запущенного nginx командой `docker compose exec nginx nginx -v`.
